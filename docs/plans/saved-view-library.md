# Saved-view library: named whole views, `save:`/`load:` commands, two cards and two pills

## Context
Saved views today are nine anonymous slots (`saved_views(slot, state_json)`, `assets_view.py:1085-1125`): `Ctrl+n` writes the working posture -- filter as `to_text()`, group-by key, rail level -- and `n` recalls it. Nothing names a view, lists them, frees a slot, or shares one, and the `holds:`/`fit:` work just made views worth keeping (a "ships short of paste" view is a question a pilot asks every week). This plan replaces the slots with a named library in the database, adds two omnibox *commands* -- `save:` and `load:`, consumed on commit and never chips -- with a Save card and a Load card on the `FilterCard` shell, two grey pills beside Clear all, `Ctrl+S`/`Ctrl+L`, and re-implements `Ctrl+n`/`n` over the library. It builds on the uncommitted advanced-omnibox-filters tree (`FilterCard`, `FitCard`, the card registry) as it is on disk.

Grilled with the user on 2026-09-05; every decision below is settled.

## Settled decisions
- A named library of WHOLE views (filter as `to_text()`, group-by key, rail level) in the database, replacing the anonymous slots. The old `saved_views(slot, state_json)` rows are DROPPED on upgrade -- no content migration; `SCHEMA_VERSION` goes 6 -> 7.
- Two omnibox commands in token form, consumed on commit and NEVER kept as chips or written by `to_text()`: `save:` (no value) opens the Save card; `save:Name` saves the current view under that name, silently overwriting, footer `Saved view 'Name' (replaced).`; `load:` opens the Load card; `load:Name` loads that view, replacing the current chips and restoring its group-by and rail level; an unknown name -> footer `No saved view named 'Name'.` and the token is consumed. `omni.parse` mints no chip for either prefix; a saved view can therefore never contain one. The draft builder (`Ctrl+F`) lists `save` and `load` as kinds whose value stage is the name; Enter on an empty value opens the card (the holds/fit empty-request precedent, inserting nothing).
- The name is one token: quote it for spaces (`save:"Jita ships"`), exactly as `fit:` wants its quotes. The Save card is where a long name is typed comfortably.
- Load replaces the current chips and bare text; the Load card shows what will be replaced.
- Save card (`FilterCard` subclass): name prefilled from a short label derived from the chips (`cat Ship · loc Jita`, or `Unfiltered`), editable and pre-selected; a `Replaces 'X'` notice when the name exists; a Copy as text button that puts the one-line grammar on the clipboard; Done saves; Enter in the name field is Done.
- Load card (`FilterCard` subclass, the `FitCard` shape): the library list with name, a slot badge (1-9 or none) and the filter text in secondary colour; a per-row slot menu (none, 1-9) -- assigning a slot takes it off any other view; inline rename on double-click; a `×` per row that forgets the view (frees its slot); a paste box that imports a shared filter line as a new view, name suggested from the text and editable in the same row of controls; Done loads the selected view. `first_focus` never lands on the list without a selection (the fit card's lesson).
- Two grey pills beside Clear all on the state row, always visible, in the order Clear all (only with filters, as today) · Save · Load, styled with `palette.pill_stylesheet` exactly like Clear all; they open the same cards anchored under the pill. `Ctrl+S` opens Save and `Ctrl+L` opens Load: tab-wide `QShortcut`, `WidgetWithChildrenShortcut`, parented on the view like `Ctrl+F`, each bound exactly once anywhere in the app.
- `Ctrl+1..9` saves the current view INTO the library view holding that slot, creating one named `Slot n` when the slot is empty; `1..9` recalls the view in that slot; footer messages keep today's shapes and add the view's name. `_KEY_MAP` rows updated.
- No new colour: the pills reuse `NEUTRAL_PILL`; the command cards own no chips so there is no tint. The draft chip in a command stage keeps its dashed "draft" look rather than taking a wash.
- One deviation from the brief, flagged for the orchestrator: the filter column is `filter_text`, not `filter`. `FILTER` is an SQLite keyword (window-function syntax); it very likely parses as an identifier through the fallback rule, but a column that may need quoting in hand-written SQL is a trap the rest of the schema avoids. The dataclass field stays `filter`.

**Amended 2026-09-05** (after the user mocked up the running Save card): a view also remembers the rail's sort. `ViewState.rail_sort` and a `views.rail_sort TEXT NOT NULL DEFAULT ''` column (`SCHEMA_VERSION` 7 -> 8, a rebuild-and-copy keyed on the column being absent -- the `sde_types.is_dynamic_type` exception, since the table is new and has no legacy column to key on) carry the rail's own key (`"value"` | `"name"` | `"volume"`, `ui/rail.py`'s `SORT_KEYS`); `''` means "not recorded" and leaves the rail's sort alone on load, the empty-`rail_level` rule. `import_text` leaves it empty. The Save card's read-only `Group by Location · Rail Owner` caption became controls between the well and the Key/Name row: a "Group by" combo mirroring the tab's own options, and the rail's header row -- level combo plus the ISK · A-Z · m³ segment -- drawn by the rail's own `LevelSortBar` (factored out of `Rail` for the purpose) so the two cannot drift. They open on the tab's posture and, like the crosses, change only what the save stores; `save_requested` is now `(name, filter_line, slot, group_by, rail_level, rail_sort)` and `_on_view_save` writes the chosen posture rather than reading the tab's. The typed `save:Name` still stores the whole current posture, sort included. The Load card's preview shows the posture a load would set in the old caption style under the chips.

## Pinned interface contracts (every package codes to these; deviations are reported, never improvised)

### db.py
- `SCHEMA_VERSION = 7`. The `saved_views` block (`db.py:504-510`) is REMOVED from `SCHEMA` and replaced, in the same "assets tab UI" section, by:
```sql
-- The saved-view library. A view is the whole working posture of the Assets
-- tab -- the filter as omni.to_text() grammar, the group-by key and the rail
-- level -- kept by name so it can be listed, renamed, shared as one line and
-- recalled from a slot. filter_text rather than filter: FILTER is an SQLite
-- keyword, and a column that may need quoting is a trap. name carries NOCASE
-- so save-by-name and the UNIQUE autoindex agree with the omnibox's own
-- case-folding; slot is UNIQUE so two views can never claim one digit, and
-- NULL slots do not collide (SQLite treats NULLs as distinct in UNIQUE).
-- Replaced the anonymous saved_views(slot, state_json) table at v7; its rows
-- were dropped, not migrated (see migrate()).
CREATE TABLE IF NOT EXISTS views (
    view_id     INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL COLLATE NOCASE UNIQUE,
    slot        INTEGER UNIQUE CHECK (slot IS NULL OR slot BETWEEN 1 AND 9),
    filter_text TEXT    NOT NULL,
    group_by    TEXT    NOT NULL DEFAULT '',
    rail_level  TEXT    NOT NULL DEFAULT '',
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL
);
```
  The section comment's last line ("Brand new tables, so CREATE TABLE IF NOT EXISTS is the whole migration") stays true for `pinned_labels` and is reworded to say so.
- `migrate()` gains a "v6 -> v7" block after the v5 -> v6 comment, keyed on the LEGACY table being present, never on `views` being absent (`SCHEMA` has already created `views` by the time this runs):
```python
    # v6 -> v7: the anonymous saved_views slots became the named views
    # library. Nothing is copied: a slot row is a filter with no name, and
    # inventing "Slot 3" names for stale filters nobody asked to keep is
    # worse than an empty library (settled with the user, 2026-09-05).
    # Keyed on the legacy table existing, per the rule above.
    if _table_exists(conn, "saved_views"):
        conn.execute("DROP TABLE saved_views")
        done.append("saved_views: dropped (replaced by the views library)")
```
- Tests (A): a v6 database built from `SCHEMA` with the `views` block stripped and the old `saved_views` CREATE appended, `schema_version` 6, one `saved_views` row, one `pinned_labels` row and one stored fit, comes out of `init()` with `saved_views` gone, `views` present, version 7, the pin and the fit intact, and `migrate()` idempotent on a second call; a fresh `init()` has `views` and no `saved_views`. `tests/test_fits.py::test_a_v5_database_gains_the_fit_tables_and_the_new_version` changes its two literal `6`s to `db.SCHEMA_VERSION`/`str(db.SCHEMA_VERSION)` (the v5 fixture still strips the fit tables; it now also carries `views`, which is fine). `tests/test_core.py::test_pinned_labels_and_saved_views_tables_exist` becomes `test_pinned_labels_and_views_tables_exist`, proving `name` uniqueness is case-insensitive, `slot` uniqueness, and that two NULL slots coexist.

### views.py (new, Qt-free; the store, the `stockpile.py`/`fits.py` precedent)
- `SLOTS = tuple(range(1, 10))`; `UNFILTERED = "Unfiltered"`; `SLOT_NAME = "Slot {slot}"`.
- `@dataclass ViewState(filter: str = "", group_by: str = "", rail_level: str = "")` -- the three-column payload. No JSON: the columns are the schema now, and `state_json` went with the old table.
- `@dataclass View(view_id: int, name: str, slot: int | None, state: ViewState, created_at: str, updated_at: str)` with `@classmethod from_row(row)`.
- `class NameTaken(ValueError)` -- raised by `rename_view` when the target name belongs to a different view; carries the offending name.
- `list_views(conn) -> list[View]`: `ORDER BY slot IS NULL, slot, name COLLATE NOCASE` (slotted views first, 1..9, then the rest by name).
- `get_view(conn, view_id) -> View | None`; `find_view(conn, name) -> View | None` (`name = ? COLLATE NOCASE`, stripped); `view_in_slot(conn, slot) -> View | None`.
- `save_view(conn, name, state) -> tuple[View, bool]`: upsert BY NAME. Blank name -> `ValueError`. `INSERT ... ON CONFLICT(name) DO UPDATE SET filter_text = excluded.filter_text, group_by = ..., rail_level = ..., updated_at = excluded.updated_at` -- the existing row keeps its `view_id`, `slot`, `created_at` and the name's stored case. Returns the row and `replaced` (`find_view` before the write, in the caller's transaction).
- `update_state(conn, view_id, state)`; `rename_view(conn, view_id, name)`: blank -> `ValueError`; a `find_view` hit with another `view_id` -> `NameTaken` (checked explicitly so the GUI never meets an `IntegrityError`); renaming a view to its own name in a different case updates the case. `delete_view(conn, view_id)` (its slot is freed with the row).
- `set_slot(conn, view_id, slot: int | None)`: `slot not in SLOTS and slot is not None` -> `ValueError`; two statements in order -- `UPDATE views SET slot = NULL WHERE slot = ? AND view_id <> ?` then `UPDATE views SET slot = ? WHERE view_id = ?` -- documented as "call inside db.transaction", the UNIQUE constraint being the backstop.
- `save_to_slot(conn, slot, state) -> tuple[View, bool]`: the `Ctrl+n` path. The slot's holder, when there is one, gets `update_state`; otherwise `save_view(conn, SLOT_NAME.format(slot=slot), state)` (which may replace an unslotted view already called `Slot n`) followed by `set_slot` on it. Returns the view and `created` (True when a new row was inserted). Never raises on a used name.
- `import_text(conn, text, name) -> tuple[View, bool]`: `spec = omni.parse(text)`; blank text -> `ValueError("nothing to import")`; the stored filter is `spec.to_text()` (canonicalised, so a hand-typed line is stored the way the omnibox would write it); `group_by`/`rail_level` empty; `name` blank -> `suggest_name(spec)`; then `save_view` (so an import under an existing name is a replace, reported through the flag). Only the filter half of a view is shareable in this slice; see Later.
- `suggest_name(spec) -> str`: `UNFILTERED` for an empty spec; else up to three parts joined by ` · `, each chip as `f"{'-' if negated else ''}{omni.prefix_for_kind(kind)} {value}"` (a bare `abyssal` chip is `abyssal` alone; a `holds`/`stat`/`roll` value is kept verbatim), bare text appended as one part, the whole cut to 40 characters with a trailing `…`. Pure, so the Load card can call it for its paste box without a connection.
- Timestamps: `datetime.now(timezone.utc).isoformat(timespec="seconds")` (the `fits.py` line).

### omni.py
- `SAVE_COMMAND = "save"`, `LOAD_COMMAND = "load"`, `COMMAND_KINDS = (SAVE_COMMAND, LOAD_COMMAND)` -- documented as the omnibox's COMMANDS, not chip kinds: `parse` never mints them, `to_text` never writes them, `where` never sees them, and `Chip.kind` is never one of them.
- `prefix_for_kind(kind) -> str`: `_KIND_TO_PREFIX.get(kind, kind)`, made public for `views.suggest_name` so the label uses the spelling `to_text` writes.
- `extract_commands(raw) -> tuple[str, list[tuple[str, str]]]`: tokenises with `_tokenize`; a token whose prefix (before the first `:`) lower-cases to a `COMMAND_KINDS` entry, is not quoted (does not start with `"`) and carries no leading `-` is a command `(kind, _unquote(value))` -- the value may be empty; every other token is kept verbatim, in order, and returned joined by single spaces as the remainder. `parse` is NOT changed and does not call this: the omnibox strips commands first and hands `parse` the remainder. Why here rather than in `omnibox.py`: the quote-aware tokeniser must stay single-sourced, and the function has to be testable without Qt. Why not a chip kind: a command is an act performed once at commit and must never be persisted, so it cannot be allowed anywhere near `FilterSpec`.
- Tests (A): `parse("save:Foo load:Bar")` is still bare text (unchanged behaviour pinned explicitly); `extract_commands` on `owner:Main save:"Jita ships" tritanium` -> remainder `owner:Main tritanium`, commands `[("save", "Jita ships")]`; an empty value is a command; `-save:x`, `"save:x"` and `save` without a colon are not; two commands come back in order; the property test grows a proof that `extract_commands(spec.to_text())` returns no commands for any generated spec (the round trip can never smuggle one in).
